Sector Rotation Tracker — Handoff Document

A US sector & theme rotation dashboard. A Python pipeline pulls prices from Yahoo Finance, computes rotation/breadth metrics, and writes a single data.json consumed by a static vanilla-JS frontend. Fully automated via GitHub Actions and hosted on Firebase — runs for free, no server.

1. Project Overview

The dashboard tracks ~36 sector/theme groups and 100 user-selectable ETFs, showing each on a Relative Rotation Graph (RRG) quadrant (Leading / Weakening / Lagging / Improving) alongside per-period returns (1D/1W/1M/3M/6M/1Y/5Y) vs SPY, breadth (% of constituents above 20DMA), and dollar-volume ratio.

Tech stack:

  • Frontend: Vanilla HTML/CSS/JS — no build tools, no framework. web/public/app.js is the single entry point.
  • Pipeline: Python 3.11 (CI) — yfinance + curl_cffi (TLS-impersonation fallback for blocked tickers), pandas, PyYAML.
  • Data store: None. cache/prices.csv + cache/volumes.csv (CSV, persisted via actions/cache, NOT in git) + the generated web/public/data.json.
  • Hosting: Firebase Hosting (target wk → sectorrotation-wk.web.app).
  • Automation: GitHub Actions daily.yml — cron 30 22 * * 1-5 (22:30 UTC, after US close).
  • Auth: None (public read-only site).

3. Core Features & Complexities

Things a newcomer will trip over if not documented:

  • Two interlocking timezone bugs (recently fixed — see readme.md 2026-07-07). The pipeline runs at 22:30 UTC. (1) _fetch_end_date() in fetch.py anchors to UTC + adds 1 day because yfinance's end is exclusive — get this wrong and CI silently produces data one day stale. (2) At 22:30 UTC, Asian/Australian markets are already on "tomorrow"; their tickers inject a future-date row that US tickers have no data for. fetch.py trims trailing rows beyond the benchmark's (SPY's) last real close before ffill(limit=2) to prevent ffill from copying US closes into future slots and zeroing every 1D return.
  • ffill(limit=2) is load-bearing. It fills interior gaps from yfinance fetch flakiness and keeps row-counting aligned with trading-day-counting for 1W/1M/3M. Do NOT remove it — verified that removing it changes those periods. It must run after the benchmark-anchored trim.
  • yfinance is flaky on GitHub Actions. Batch downloads fail non-deterministically (SystemError, TypeError: expected string or bytes-like object). The Yahoo chart-API fallback in _fetch_via_yahoo_chart_api (using curl_cffi with impersonate="chrome") is what makes the pipeline reliable — it typically recovers 30–300 tickers per run. A "successful" run still emits many Warning: ... lines; that is normal.
  • Breadth for leveraged/inverse ETFs is inherited from a parent via the breadth_source key in etf100.yaml (e.g. TQQQ → QQQ). Without it, leveraged ETFs show null breadth because they have no holdings of their own.
  • RRG weekly resample workaround. metrics.py to_weekly() filters to Fridays (dayofweek == 4) instead of .resample() to avoid a pandas C-extension segfault on Python 3.14. (CI runs 3.11 where it's fine, but local dev may hit it.)
  • Frontend personalization (period selection, ETF picks, vs-SPY period) is stored in browser localStorage — no backend, no login.

4. Security Architecture

Heads up: A Firebase service-account key (FIREBASE_SERVICE_ACCOUNT.json) exists in the working tree for local deploy tests. It is gitignored and must never be committed. CI uses the FIREBASE_SERVICE_ACCOUNT GitHub Actions secret instead.
  • No auth, no PII. The site is public read-only. No user accounts, no database writes, no form submissions.
  • Secret handling: .gitignore blocks FIREBASE_SERVICE_ACCOUNT.json, *-firebase-adminsdk-*.json, and sectorrotation-*.json. CI injects the key via repo secret, never logs it.
  • Deploy permissions: The GITHUB_TOKEN (auto-injected) is used for both the git push of data.json and the Firebase deploy step. permissions: contents: write is set explicitly in daily.yml.

5. Local Development Setup

Python 3.11+ recommended. Avoid Python 3.14 for running the pipeline locally — pandas 2.2.2 has C-extension SIGBUS crashes in tz_convert and Timedelta arithmetic on 3.14 (the code works around some, but running the full fetch locally on 3.14 is unstable). CI uses 3.11.

  1. # Clone and enter
git clone https://github.com/Thailaxy/SectorRotation.git
cd SectorRotation
  2. # Virtual env + deps
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
  3. # Run the full pipeline (needs network access to Yahoo Finance;
# will fail on networks that block/intercept it — works in CI)
python -m pipeline.run
# → writes web/public/data.json
  4. # Serve the frontend locally
cd web/public
python -m http.server 8000
# open http://localhost:8000
  5. # Preview WITHOUT a network fetch (uses the committed data.json)
cd web/public && python -m http.server 8000

6. Deployment

Deployment is fully automated via .github/workflows/daily.yml. There is no manual deploy step in the normal flow.

  1. Scheduled: cron 30 22 * * 1-5 (Mon–Fri 22:30 UTC).
  2. Manual: GitHub Actions UI → "Run workflow" on the daily-update workflow (uses the workflow_dispatch trigger).

The workflow runs, in order:

  1. Restore cache/ via actions/cache@v4 (key cache-v1-$GITHUB_RUN_ID, fallback cache-v1-).
  2. If cache miss: python seed_real_cache.py (cold start, ~3–5 min).
  3. python -m pipeline.run → writes web/public/data.json.
  4. Commit + push data.json as rotation-bot.
  5. 1st Monday of month: refresh data/holdings.yaml.
  6. Deploy to Firebase Hosting (live channel, target wk).

Live URL: sectorrotation-wk.web.app

Cache headers (set in firebase.json): data.json = 5 min, JS/CSS = 1 hour, HTML = no-cache.

8. Testing

Run the test suite with:

pytest tests/

Current coverage:

  • tests/test_metrics.py — unit tests for period_return, calc_pct_above_ma, calc_dollar_vol_ratio, classify, and RRG reproducibility.
  • tests/test_fetch.py — regression tests pinning: (a) _fetch_end_date is timezone-independent (CI vs local agree); (b) the benchmark-anchored trim prevents international-ticker future-date rows from zeroing 1D returns.
End-to-end verification (not automated): after a CI run, confirm the live site's 1D column shows real values (not all 0.00%) and as_of_date in the header matches the latest US trading day.
