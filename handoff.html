Project Handoff & Onboarding

Welcome to the US Sector & Theme Rotation Tracker. This document provides a high-level overview of the project architecture, tech stack, and setup instructions to get you started immediately.

Note: For historical logs of what decisions were made and why, please refer to readme.md in the repository root.

1. Project Architecture

The system is a fully static website powered by a Python data pipeline. It runs completely for free using GitHub Actions and Firebase Hosting.

  • Frontend: Vanilla HTML, CSS, and JavaScript. No build tools (no Webpack, Vite, React, etc.). UI logic lives in web/public/app.js.
  • Backend / Pipeline: Python scripts that fetch data from Yahoo Finance via yfinance and curl_cffi (to avoid bot blocking), perform calculations (RRG, returns, breadth), and output a single data.json file.
  • Hosting: Firebase Hosting (migrating from GitHub Pages).
  • Automation: GitHub Actions runs the Python pipeline daily after market close, saves the data cache, and deploys the updated data.json and frontend to Firebase.

2. Key Files & Directories

Path Purpose
config.yaml Core configuration: benchmark ticker, return periods, RRG lookback lengths.
data/universe.yaml The master list of themes, sectors, and their constituent tickers.
pipeline/run.py Entry point for the data pipeline. Executes fetch and build steps.
pipeline/fetch.py Fetches market data from Yahoo Finance. Uses curl_cffi to bypass blocks.
pipeline/build_json.py Aggregates fetched data and metrics into the final data.json.
web/public/ The static frontend. Contains index.html, app.js, styles.css, and the generated data.json.
cache/ Local CSV files holding historical prices and volumes to reduce API calls. (Moving to GitHub Actions cache).

3. Local Development Setup

You need Python 3.11+ installed. No database required.

# 1. Clone the repo
git clone <repo-url>
cd Rotation

# 2. Create and activate a virtual environment
python -m venv .venv
source .venv/bin/activate  # (On Windows: .venv\Scripts\activate)

# 3. Install dependencies
pip install -r requirements.txt

# 4. Run the data pipeline to generate web/public/data.json
python -m pipeline.run

# 5. Serve the frontend locally
cd web/public
python -m http.server 8000
# Open http://localhost:8000 in your browser

4. Testing

Run unit tests using pytest to ensure metrics logic remains correct:

pytest tests/

5. Upcoming Major Features (Pending Execution)

We have a finalized implementation plan awaiting execution (intended for GLM5.2 agent):

  • 100-ETF Custom Heatmap: Users will be able to select up to 20 ETFs from a predefined list of 100 to view on the heatmap.
  • LocalStorage Personalization: User ETF choices and preferred return periods (1D, 1W, 1M, 3M, 6M, 1Y, 5Y) will be stored in the browser's `localStorage` (no backend).
  • Holdings Generation: A new script scripts/generate_holdings.py will fetch top-10 holdings for ETFs monthly to compute breadth. Leveraged ETFs (like TQQQ) will inherit holdings from their parent (QQQ) via a new breadth_source config key.
  • Firebase Migration: Full transition of hosting to Firebase to better control Cache-Control headers.
